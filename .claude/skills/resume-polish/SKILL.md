# 简历精修（阿酥版式）

把真实经历写成招聘方一眼能读懂、可追问、有证据的简历，并在排版上做到"刚好一页、每条刚好满行"。内容方法沿用阿酥 `/great-resume`，版式沿用 `/make-resume` 的 ASu 模板，本技能补上多轮实战中沉淀下来的精确参数、脚本和坑。

## 每次交付：两个用途、两种日期精度

每一轮修改都同时维护两份内容相同、只差日期精度的源文件（`content.html` 精确到日，另一份把 `YYYY.MM.DD` 换成 `YYYY.MM`），并交付：

| 文件 | 日期 | 用途 |
|---|---|---|
| `<名>.pdf` | 到月（2024.07 – 2024.11） | 上传给 HR 的投递版，排版在任何设备都不变 |
| `<名>_网申.docx` | 精确到日（2024.07.31 – 2024.11.01） | 用户填网申时照抄日期、自己改字用 |
| `<名>_p1.png` 等（300 dpi，月份版） | 到月 | 用户在手机上圈点、写批注，截图发回 |

命名：`姓名_岗位_最强标签_届别`，如 `邹志华_AI产品经理_NUS硕士_27届`、`邹志华_AI解决方案_NUS硕士_27届`。岗位用中文全称（HR 按岗位名搜索），最强标签放学历或名企。

交付后用一张表或短列表说明"改了什么、为什么"，并单独列出需要用户确认的推断性措辞或照搬来的数字。

## 工作流

1. **读材料再动笔**：现有简历/截图、GitHub 仓库（含 `/evidence`）、用户提供的 PDF。数字只用有出处的；从别的版本照搬、无法核对的数字要在交付说明里点名。
2. **定岗位与人设**：一份简历只服务一个岗位。AI 产品经理版和解决方案/FDE 版要分开写，互不"污染"——具体用词差异见 `references/writing-rules.md`。
3. **重写内容**：按 `references/writing-rules.md` 的结构和详略规则逐段改写。
4. **排版**：复制 `assets/template.html` 为工作目录下的 `content.html`，把 `assets/logos`、`assets/icons` 复制到同目录，填入内容。设计参数见 `references/design-spec.md`，不要凭感觉改字号。
5. **构建与测量**：
   ```bash
   bash scripts/build.sh <workdir> <文件名>        # 产出 out/<名>.html/.pdf/.png/.docx，并打印页面余量
   NODE_PATH=$(npm root -g) node scripts/lines.cjs <workdir>/out/<名>.html   # 每条的行数与末行占满比例
   ```
6. **调到"刚好"**（最花时间的一步，按下面顺序迭代，每改一轮就重跑 5）：
   - `measure` 的 `over` > 0 → 超页：先把"差一两个字就多一行"的条目压回一行（收益最大），再按详略删最弱的内容，最后才动行距。
   - `lines` 标出末行 < 86% 的条目 → 要么删几个字压成整行，要么补**真实**细节写满；只有"我的职责：……"这类引出子要点的引导句可以不满。
   - 页尾有明显空白（`over` < -20px）→ 用素材里现成的内容补一行整条，而不是放大字号。
   - 最后看一眼 PNG 截图确认视觉，再交付。
7. **Word 校验**：`build.sh` 会用 LibreOffice 估算 docx 页数；超页就降 `docx_line_twips`（第三个参数，常用 200–216），一页后再留约 4 twips 余量。
8. **需要引用报告/作品时**：按 `references/evidence-publishing.md` 上传到 GitHub `evidence/` 并在公司条右侧加 `Product Report ↗` 链接；链接指向 `main`，PR 需合并后才生效。
9. **缺 Logo 时**：按 `references/logos.md` 的来源和裁剪方法处理；实在找不到就请用户发截图，不要画仿冒 Logo。

## 用户偏好（多轮反馈沉淀）

- 用户明确说"按我说的改，不用确认"时直接改，改完再报告；只有真正会改变事实的地方才问。
- 视觉（2026-10 定稿版，`<body class="mono">`）：正文、组织、岗位全部黑色；只有分区标题、标题下 1pt 横线、项目报告/项目链接用同一种蓝 `#1f57bf`。不要灰底公司条。
- 字体与间距（2026-10 定稿）：正文宋体 + Times New Roman，8.7pt，行距 1.32；分区标题也用宋体加粗 12pt 蓝色；经历块间距 6.5pt，分区间距 10px，上下页边距 10mm。
- 页眉：姓名左侧，电话/邮箱/GitHub 紧挨姓名，一起压在蓝线上（`.topbar`），不再单独写"个人介绍"标题。
- 标题行：`[图标] 组织 · 岗位 · 项目报告 | 关键词 · 关键词 · 关键词`，日期右对齐；组织、岗位、日期同为 9pt 加粗，关键词常规字重，正文文字与组织名左对齐。三个关键词针对投递岗位概括这段经历。
- 正文每条刚好一行、两端撑满（`text-align-last: justify`），结尾不加句号，最后一个字与日期右端对齐。加粗只给数字和结果，每条最多一两处。
- 公司名用中文正式名（如 红杉中国、奇绩创坛），职位写正式职位名，不擅自加 "AI"。学校、暑期项目名称以证书原文为准，不夸大主办方。
- 实习按时间倒序；开源/GitHub 项目放在项目经历最后。
- 求职意向要自然：主岗位 + 专长方向，不要罗列一串岗位、不要写"均可"。
